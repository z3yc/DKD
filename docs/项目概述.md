# DKD 帝可得智能售货机平台 · 项目概述

> 面向第一次接触本项目的人：**这是什么、给谁用、有哪些功能、现在能用到什么程度**。
> 细节口径分别在 `DKD业务规范-清晰版.md`（业务）与 `AGENTS.md`（工程）；本文只做全貌。
> 当前版本 **v0.4.1**（2026-11-02），`develop` 分支，CI 5/5 绿。

---

## 1. 一句话

**一套给自动售货机运营商用的「设备资产 + 作业 + 交易 + 报表」管理平台**，并在旁路挂了一个
**智能体（LLM）能力层**：自动算补货建议、辅助故障诊断、把每次 AI 决策留痕可审计。

## 2. 解决什么问题

运营方通常有几十到几百台售货机，散落在不同城市/点位（门店、楼宇），需要回答四个问题：

| 问题 | 平台给的能力 |
| --- | --- |
| **货卖得怎么样？** | 订单/营收报表、区域与设备排行、AI 日报解读 |
| **什么时候该补货？** | 库存预警 + 规则版建议 + **智能体补货建议**（7/14/30 天分位销量 + LLM 校准） |
| **设备坏了怎么办？** | 故障诊断（证据/未知项/置信度）→ 派单提案 → 人工确认建维修工单 |
| **谁在干活、干得怎样？** | 工单状态机、运维端接单/完成、员工排名、决策审计 |

## 3. 谁在用（角色）

| 角色 | 主要在哪个端 | 典型操作 |
| --- | --- | --- |
| 运营管理员 | 管理后台（Web） | 建区域/点位/设备、配货道与商品、看报表、审 AI 建议 |
| 运维/维修工程师 | 运维移动端（`dkd-app`，H5/App） | 接单、完成（补货/维修/投放/撤机）、查设备 |
| 合作商（点位主） | 独立账号（同库） | 看自己点位/设备的经营数据（分成计算尚未实现） |
| AI 助手使用者 | 后台任意页面右侧抽屉 | 用自然语言问数据、要补货建议、查故障 |
| 平台/开发运维 | 配置与部署 | `agent.enabled` 开关、凭据轮换、CI 与演练 |

## 4. 系统组成（四个端 + 一条旁路）

```
        ┌────────────────────── 管理前端 dkd-vue（Vue3 + Element Plus，:80）──────────────────────┐
        │  业务页面（设备/点位/商品/订单/工单/报表…）   AI 助手抽屉（SSE 流式）  智能体 3 页           │
        └───────────────────────────────────┬──────────────────────────────────────────────────────┘
                                            │ /prod-api 反代
        ┌───────────────────────────────────▼──────────────────────────────────────────────────────┐
        │ 管理后台 dkd-parent（Java 8，Spring Boot 2.5，:8080）                                     │
        │  dkd-admin(启动/系统) · dkd-framework(安全) · dkd-system(系统域) · dkd-manage(业务域)      │
        │  dkd-common(工具+AI兜底+Agent网关) · dkd-quartz(定时) · dkd-generator(代码生成)           │
        └───────────────┬───────────────────────────────┬──────────────────────────────────────────┘
                        │ 共用 dkd MySQL 库              │ /agent/** 网关转发（JWT + 权限点）
        ┌───────────────▼──────────────┐   ┌────────────▼──────────────────────────────────────────┐
        │ 运维移动端 dkd-app（Java 11，│   │ 智能体服务 dkd-agent（Python 3.11 / FastAPI /         │
        │ Spring Boot + MyBatis-Plus） │   │ LangGraph，:8090，只监听回环）                         │
        │ 只含运维作业域（:9070）      │   │ 补货图 / 诊断图 / 故障派单 / 审计留痕 / 成本限额       │
        └──────────────────────────────┘   └────────────┬──────────────────────────────────────────┘
                                                        │ 只读业务表（白名单）+ 写 agent_* 自有表
                                                        │ 业务写操作 → 回调 Java REST（服务间密钥）
```

**关键边界（设计红线）**
- **Java 是业务事实唯一所有者**：所有业务写操作必须经 Java 的校验链与事务；
- 智能体**只读**业务表（MySQL 只读账号 + 表白名单，且 SQL 表名与声明双向校验），
  写操作一律回调 Java（`/agent/callback/task`）；
- 智能体自有表 `agent_*`（会话/留痕/补货计划/暂停开关）由 Agent 自维护，不授 DELETE；
- **LLM 不可信**：结构化输出容错解析 + 范围夹取；写操作必须人工确认（human-in-the-loop）；
- `agent.enabled=false` 或 Python 不可用时，主业务零影响（旧单轮 AI 链路兜底 + 前端降级）。

## 5. 功能地图（按业务域）

### 5.1 组织与档案
- **区域 / 点位（含商圈类型、Excel 导入、AI 选址）**
- **合作商**（分成比例字段、独立账号）
- **员工与角色**（工单执行人：区域 + 角色 + 启停用）
- **系统管理**（用户/角色/菜单/部门/字典/参数/日志/定时任务/在线用户）

### 5.2 设备与商品
- **设备型号**（行×列×单货道容量 → 建设备时自动生成货道）
- **售货机台账**（设备状态、所属点位/区域/合作商）
- **货道**（绑定商品、容量、当前库存缓存）
- **商品/分类**（价格以「分」存储、前端按元录入）
- **策略**（折扣档案；注：目前无业务代码消费，属预留）

### 5.3 交易与库存
- **订单**：查询/详情/导出、取消（仅待支付）、退款（仅出货成功）；
  订单由仓外系统写入，平台以「全快照」方式只读+两个动作；
- **库存台账**（按货道：当前/预警/最大）+ **库存流水**（唯一变更入口）；
- **销售扣减**：订单落库为「出货成功」时回写库存台账并写流水（`order_id` 可追溯）。

### 5.4 作业（工单）
- **四类工单**：投放、补货、维修、撤机；统一建单校验链（类型白名单、员工启用+角色匹配、
  货道归属、数量/容量、SKU 一致性、防重）；
- **状态机**：待接单 → 进行中 → 已完成 / 已取消（仅经状态机迁移）；
- **运维端**：接单/取消（条件 UPDATE 防并发覆盖）、完成（按类型产生副作用，同事务）。

### 5.5 报表与决策
- **日报/周报**（营收、订单、设备故障、低库存）+ **AI 解读**（失败降级为纯数据）+ 排行；
- **库存预警**（缺货/低库存，分页）；
- **规则版补货建议**（目标 85% 容量、下限 2×预警值）。

### 5.6 智能体能力（旁路增值层）
| 能力 | 说明 |
| --- | --- |
| **补货 Agent** | 定时（06:00）或手动分析 → 7/14/30 天分位销量 + 容量约束 → LLM 校准系数（不改数量，只调系数）→ 生成计划；运营在工作台「确认/调整/跳过/暂停」后建补货工单 |
| **诊断 Agent** | 多轮问诊（焦点设备做成状态）+ 异常检测 + 历史工单线索 + **结构化结论**（证据/未知项/平台动作/证据强度置信度，**刻意不含病因**）→ 派单提案 → 人工确认建维修单 |
| **问诊循环** | 固定排查清单（定位→出货/库存异常→库存明细→在途工单→历史线索），过早下结论会被替换成清单下一步 |
| **决策审计** | 每次 AI 决策留痕（输入上下文/模型输出/动作/结果/token），可按 `request_id` 回放整条链路 |
| **AI 助手** | 后台右侧全局抽屉，四个场景（通用/补货/诊断/分析），SSE 逐 token 流式，支持中断、续传、降级 |

## 6. 三条核心闭环（看懂这三条就看懂系统）

1. **补货闭环**：库存预警 → （规则版/Agent）建议 → 工作台人工确认 → 建补货工单 →
   运维端接单/完成（同事务写货道缓存 + 库存台账 + 流水）。
2. **故障闭环**：设备异常 → 诊断（证据/未知项/置信度）→ 派单提案（接单人/优先级/依据）→
   人工确认 → 建维修工单 → 运维端维修（作业回执仍在建设）。
3. **审计闭环**：任何 AI 写操作决策 → `agent_decision_log` → 审计页回放 + 按 request_id 串起
   「状态机放行 → 回调建单 → 回写状态」。

## 7. 技术架构要点

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3.4 + Element Plus + Vite（**JavaScript，无 TS**） | RuoYi-Vue3 改造；Pinia；axios 统一拦截器；SSE 自研客户端 |
| 后台 | Java 8 / Spring Boot 2.5 / MyBatis / Druid / Redis / Maven 多模块 | 端口 8080；RuoYi JWT 权限链 |
| 运维端 | Java 11 / Spring Boot / MyBatis-Plus / JWT | 端口 9070；独立签名密钥（fail-closed） |
| Agent | Python 3.11 / FastAPI / LangGraph / SQLAlchemy(async) | 端口 8090；checkpoint 默认 SQLite，可切 PostgreSQL |
| 存储 | MySQL（业务，单主库）/ Redis 3.2（令牌、验证码；**不能**承载 checkpoint）/ SQLite 或 PG（Agent 会话） | 无 Redis Streams、无模块系统 |
| 集成 | Java→Python：HTTP + SSE（`/agent/**` 网关，JWT + 权限点）；Python→Java：REST 回调（服务间密钥 + 路径白名单 + 限流） | 全链路 `request_id` |
| 质量 | JUnit 166 + dkd-app 16 + pytest 538 + ruff + 前端构建 + compose 配置校验 | GitHub Actions 5 个 job |

## 8. 现在能用到什么程度（如实）

**已可用**
- 组织/设备/商品/点位/货道/订单/工单/报表的全套管理；
- 补货 Agent 闭环（含工作台、暂停开关、审计）；
- 诊断 Agent（证据/未知项/结论卡片/派单确认）；
- 决策审计与运行时间线；AI 助手四场景对话；
- 销售扣减接线、接单并发防护、SQL 表白名单强制校验、统一 CI。

**已知边界**
- **交易链路只覆盖平台入库这一条路径**，外部系统若直写订单表则不会触发扣减；
- **案例库未建**（维修工单数据不达标，按预案降级为规则库）；
- **合作商分成未实现**（口径待业务拍板，仅出规格）；
- 库存/容量存在历史不一致（`tb_inventory` vs `tb_channel`），等待业务确认权威源；
- 部分验收需真实环境：真机 M2、移动端备注可见性、浏览器手测、停服务降级演练。

## 9. 快速上手

```powershell
# 1) 基础设施：MySQL + Redis（+ 生产可选 PostgreSQL）
# 2) Python 智能体（必须用这个入口，Windows 事件循环限制见 AGENTS §1）
cd dkd-agent; set -a; . ../.env; set +a; uv run python -m app
# 3) Java 后台（用脚本，别手敲 java -jar：会静默复用旧 jar）
pwsh -File docs/scripts/start-backend.ps1
# 4) 前端
cd dkd-vue; npm run dev        # 默认 http://127.0.0.1，账号 admin/admin123
```
