# 智能补货工作台 · 运营操作指引（排期任务 4-1）

> 面向：运营 / 运维人员（不需要了解技术实现）
> 入口：管理后台左侧菜单 **AI 智能体 → 智能补货工作台**
> 相关：`docs/agent-operations-runbook.md`（故障处置）

---

## 一、每天怎么用（三步）

页面顶部有引导条：**1 查看建议清单 → 2 调整或跳过异常项 → 3 确认创建工单**。

1. **看**：Agent 每天 **06:00** 自动分析并生成当天的建议清单。
   顶部统计卡告诉你「待处理几台设备 / 其中紧急几条 / 合计多少件」。
2. **处理异常**：绝大多数建议直接确认即可；对明显不合理的，用**调整**或**跳过**（原因必填）。
3. **确认建单**：确认后系统会创建补货工单，工单会流转到运维的手机端去接单执行。

> 顶部「全部确认建单（N）」= 逐条帮你确认。
> **某台失败不影响其它台**，结束后会弹出汇总告诉你哪几台没成功——请按提示单独处理。

## 二、每个按钮做什么

| 按钮 | 作用 | 注意 |
| --- | --- | --- |
| **确认建单** | 按建议量创建补货工单 | 已建单的再点不会重复建（幂等） |
| **调整** | 改建议量，或让系统按新参数重算 | 两种方式**只能选一种**（同时用会被拒绝：系统分不清你的意图） |
| **跳过** | 这条建议本期不做 | 跳过是**终态**；当天可以用「恢复建议」撤销 |
| **恢复建议** | 把已跳过的重新变成待处理 | **仅限当天**；跨天的请等次日分析重新生成 |
| **暂停自动分析** | 次日 06:00 不再生成新建议 | 当前清单**仍可正常处理**；适合盘点期、大促前人工统一排单 |
| **恢复自动分析** | 恢复次日自动生成 | — |

**调整弹窗里的两种方式**：

- **指定数量**：直接填你要补的件数。上方会显示上限（= 货道容量 − 现库存），填多了系统会拦住
  ——因为补进去会溢出货道。
- **按新参数重算**：改「预测窗口」（7/14/30 天）或「服务水平」，由系统重新算建议量。
  **不是你口算**——重算用的数据和 06:00 那次分析完全一样。
- 两种方式都**必须填/选原因**。原因会写入决策留痕，用于后续优化预测（所以不能随便填）。

## 三、状态标签含义

| 标签 | 含义 | 你能做什么 |
| --- | --- | --- |
| **建议** | 待处理 | 确认 / 调整 / 跳过 |
| **已调整** | 你改过 | 确认 / 跳过 |
| **待指派** | 没匹配到同区域的接单人 | 先确认，系统会按待指派处理；也可联系运维补人员区域 |
| **已跳过** | 本期不做 | 当天可「恢复建议」 |
| **已建单** | 工单已创建 | 无需操作（会显示工单号） |
| **已复盘** | 已回看 | 终态，不可再改 |

**接单人**：系统按 **设备所在区域** 自动匹配同区域的运维人员。
若显示「待指派」，说明该区域没有可接单的人——这是数据问题，请反馈给管理员（不是系统故障）。

## 四、常见情况怎么处理

| 情况 | 你看到的 | 你该做什么 |
| --- | --- | --- |
| 确认建单后提示失败 | 红字提示，例如“建单失败：…”。**计划状态没有变**（还是「建议」） | **再点一次「确认建单」即可重试**。若连续失败，把提示原文发给运维 |
| 提示“已建单的计划不能重复确认” | 橙色提示 | 刷新页面看最新状态，不要重复点 |
| 提示“正在建单中” | 橙色提示 | 稍等几秒刷新；说明刚才有一次确认正在处理中 |
| 提示“调整必须填写原因” | 黄色提示 | 选一个原因或自己写一句（必填） |
| 页面顶部出现黄色横幅 | “已暂停自动补货分析：明日 06:00 不再生成新建议” | 说明自动分析被暂停了；当前清单照常处理。点横幅里的「恢复自动分析」即可继续 |
| 清单是空的 | 表格显示“当日暂无补货计划” | 可能是：① 自动分析被暂停；② 当天 06:00 任务未跑成功。**不要手工造数据**，先反馈运维 |
| 某台设备的「依据」里写着「降级·规则兜底」 | 展开行可见 | 说明该设备近 30 天没有销量数据（新上线/断网/数据延迟），系统按规则兜底给了建议。**请人工核实后再确认** |
| 商品名显示「（未命名商品）」 | 展开行可见 | 商品档案缺名称，不影响补货；可反馈管理员补齐档案 |

## 五、两个统计卡为什么是「—」

页面顶部第二、三张卡（预测 7 日缺货率 / 上期建议准确率）当前显示 **「—」**，并标注了「待接入」。

这是**故意的**：这两项需要等「规则版并行对比」（任务 1-14）与「补货复盘自动化」（任务 3-6）
产出数据后才有来源。在数据源接入之前**留空而不是填演示数字**——
验收和汇报时才能分清哪些数字是真的。

## 五·补、AI 助手现在能回答什么（2026-10-01 更新）

助手**已经能查真实数据**了（只读）。可以直接问：

| 你可以这样问 | 助手会做什么 |
| --- | --- |
| 「先看紧急的」「今天有几条要补的」 | 查当日补货建议，列出紧急项与理由 |
| 「A1000001 库存怎么样」「哪个货道快空了」 | 查该设备档案与各货道库存/容量 |
| 「这台是不是已经有单了」「为什么建不了单」 | 查在途工单（同设备同类型有在途单时会被防重拒绝） |
| 「这台最近卖得怎么样」「为什么建议补这么多」 | 查近 7/30 天出货成功销量与金额 |

**它不能做的（问了也会被引导到页面）**：

- 不能建单、确认、调整数量、跳过、暂停 —— 这些必须你在**补货工作台**里点（这是故意的：
  写操作必须人工确认，否则模型理解错一次就会真的多派一张单）。
- 不能改设备/商品/库存/员工档案。

**两个使用提示**

1. 助手回答里若出现「容量可能不准 / 数据不一致」，说明该设备的库存表与货道档案不一致
   （已知数据质量问题），**别直接按它给的缺口补货**，先确认口径。
2. 若回复是 `[echo] 你的问题`，说明服务当前跑在**回显模式**（未启用真模型），
   页面顶部会有蓝色提示条说明；此时任何问题都不会真的被解答，请让运维打开真模型。

## 六、决策审计页（管理员/审计用）

入口：**AI 智能体 → 决策审计**。

- 这里记录**每一次**对业务数据的写操作决策：成功、重复点击、被拒绝、失败四条路径都留痕。
- 可按场景/触发方式/结果/动作/目标/请求号/时间范围筛选；点「详情/回放」看当时的输入上下文。
- **只能看，不能改也不能删**：留痕是审计证据，一旦可改就不再是证据。
- 排障时最有用的字段是 **追踪ID（request_id）**——把它给运维，能精确定位那一次请求的全链路日志。
