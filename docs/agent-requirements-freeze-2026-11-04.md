## 2. 裁剪顺序（可执行：人力/时间不足时，从序号小到大裁）

> 规则：**只裁 P1/P2，不裁 P0**；P0 时间不够只能顺延（见 §0 变更规则）。
> 每步写明「裁什么 / 连带 / 影响 / 回退成本」，避免“裁了上游、留着下游”的悬空依赖。

| 序 | 裁什么 | 连带必须一起裁 | 影响 | 恢复成本 |
| --- | --- | --- | --- | --- |
| ① | 6-8 效果评估（P1） | 无 | 观察期结束没有正式评估报告，只有驾驶舱数据 | 低（数据在库，补报告 1~2 天） |
| ② | 5-5 成本优化（P1） | 无 | 不做主动降本；429 仍可在驾驶舱看到用量 | 低 |
| ③ | 5-4 规则对比（P1） | 无 | S7 少一卡；其余四卡与告警条不受影响 | 低 |
| ④ | 4-4 保留清理（P1） | 无 | 手工清理脚本代跑；30 天日志清理暂时靠运维 | 中（胀库后补做要停机窗口） |
| ⑤ | 3-5 模型档案（P1） | 无（3-4 可保留） | S14 不做；模型连通性靠日志与 `ping_llm` 脚本 | 中（后端表与页面都要补） |
| ⑥ | 3-7 MCP（P2） | 无 | 工具全部内置，可插拔能力没有；四道闸不落地 | 高（安全闸要重新评审） |
| ⑦ | 3-6 知识库 L2（P2） | **连带 5-3 引用治理**；若 1-5 未落地则 1-5 一并裁 | 只能回答“数据是什么”，不能回答“为什么/怎么办”；S11 仅留“未启用” | 高（语料+向量+评测都要补） |
| ⑧ | 3-4 工具注册表（P1） | **连带 3-5、3-6、3-7**（下游） | 工具开关仍需发版；S12/S14 无底座 | 高（改代码才能关工具） |

**不可裁的组合（硬约束）**：

1. `2-1 + 2-2 + 2-3 + 2-7` = 配置底座最小闭环（缺一“配置可见但行为不变”或“行为变但不可回滚”，等于没有）；
2. `3-1 + 3-2 + 3-3` = 自定义智能体最小闭环（3-2 依赖 2-9，3-3 依赖 3-2）；
3. `1-4 + 5-1` = 评测护栏闭环（无评测集则 5-1 无输入；无 5-1 则评测集是死文件）；
4. `1-3 + 6-1` = 驾驶舱口径闭环（无指标字典则 S7 数字各算各的）；
5. `2-4`（日志）与 `2-5`（会话）虽可分批交付，但**都在 P0**，不可裁，只能顺延。
