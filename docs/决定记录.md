## 2026-11-02 · 模板页 loading 用 `.finally` 而不是重写成 async/await

RuoYi 模板页都是 promise 链（`listXxx().then(...)`）。在链尾加 `.finally()` 每个文件只 +1 行、
成功路径赋值顺序完全不变，回归面最小；重写成 `async/await + try/finally` 会动 18 个页面的函数体，
收益相同但风险大得多。

## 2026-11-04 · 工具注册表与模型档案的字段口径（3-4/3-5）

- `agent_tool`：本地工具与 MCP 工具同表；`code` 必须能映射到代码/工具名，**库内存在无法映射的 code
  时拒绝启动**（表不存在则 WARN + 回代码默认，兼容旧环境）。`enabled` 在运行期强制过滤；
  `timeout_ms/row_limit` 对本地工具是声明值（实际读取护栏仍由 `read_tools` 5s/2000 行统一兜底），
  对 MCP 工具由接入层强制 ≤5000ms / ≤200 行（3-7）。
- `agent_llm_profile`：只存**连接信息**（provider/base_url/model/api_key_env），采样参数仍在
  `agent_config`（避免“到底听谁的”）；`api_key_env` 只存环境变量名，页面永不回显密钥；
  `is_default` 最多一个由应用层保证；探测记录 `agent_llm_probe` 只增不改，不落响应正文/密钥。

## 2026-11-04 · 知识库 L2 的降级技术路线（无外部 embedding 依赖）

本机没有可用的 embedding 服务/密钥，`pgvector` 是否可用待现场确认。L2 先按**本地向量化**
（哈希/TF-IDF 类，纯 Python 标准库 + numpy，无新增外部依赖）实现语料切片/检索/引用强制校验，
存储用 MySQL 自有表（或 PG，若 pgvector + 授权就绪再切换）；L3 案例库继续「未启用·数据未达标」。
原因：引入 sentence-transformers/外部 embedding 会带来新依赖、模型体积与成本，且当前语料授权未完成，
先保证「检索→引用→回退仅列证据」的闭环可测，换 embedding 只需替换向量化适配层。

## 2026-11-04 · MCP 实现口径（C2 落地时拍板）

- **本期 transport 只开 HTTP JSON-RPC**；stdio 需要在本机拉起外部进程，安全面/生命周期不同，明确拒绝并给原因。
- **只读是硬闸**：只有 `annotations.readOnlyHint is True` 的工具允许同步/调用；缺失或 false 一律拒绝，
  不做“看起来像查询就当只读”的猜测。写工具永远不会进入模型工具集。
- **启动探测失败 = 拒绝启动**：启用的 server 探测失败直接 `RuntimeError`（带 server code 与原因），
  不静默跳过——否则页面显示“已启用”而模型少一组工具，排障极难。
- **MCP 工具只注入诊断场景（scene=3）**：外部工具能力面不受本仓控制，本期先收敛；
  自定义场景选择 MCP 工具需要 Java meta 与 code 映射一起改，未做即不写“已支持”。
- **`/agents/mcp/call` 对未同步/写工具返回 404**（“工具未同步或不存在”）：行为是拒绝，
  与任务书写的 400 有状态码差异，已登记；管理台不代理 tools/call，避免开“任意外呼”入口。
- **MCP HTTP 客户端刻意 `trust_env=False`**：本机系统代理会把 127.0.0.1 的 MCP 请求也发给代理并返回 502
  （2026-11-04 实测）。MCP endpoint 是运营显式配置的受控出网点，代理必须显式配置，不继承隐式环境代理。
- **授权扩到写**：Python 探测后需回写 server 状态、同步 mcp 工具行，因此 `agent_mcp_server` 授 SELECT/UPDATE、
  `agent_tool` 授 SELECT/INSERT/UPDATE；风险（MySQL 无列级/行级授权）已在 DDL 文件注释，后续可改为 Java 回调写入。

## 2026-11-04 · 会话持久化与上下文治理口径（4-1/4-2/4-5）

- **会话头由 Python 写、Java 只读**：`agent_conversation` 的 `message_count` 是冗余列，用于列表排序/对比；
  由 `touch_conversation` 每轮累加（delta=2），页面若发现 message_count 与消息行数不一致会显式提示漂移。
- **seq 只存 user/assistant**：工具消息不进 `agent_message`（审计用 `agent_decision_log`/`agent_run`），
  因此 seq 连续（1=user, 2=assistant, 3=user…）；工具调用明细放在 assistant.tool_calls JSON 里。
- **config_version 不伪造**：两表列可空；取不到本轮实际生效快照就写 NULL，页面显示“—（历史数据）”。
  配置回滚**不回写**历史消息（4-2 验收口径：旧会话行为可解释，而不是把旧消息改成新版本）。
- **工具耗时是包装层测量**：ToolNode 工具轻量包装记录 `durationMs/resultRows/resultChars`，参数摘要脱敏≤300；
  异常语义原样保留（仍由 `_handle_tool_error` 兜底）。
- **上下文预算用启发式 token 估算**（中文≈1 字/token、其他≈4 字符/token），不是 tokenizer；
  超预算保留最近 12 条、旧工具结果摘要化、丢最旧并 WARNING。真实 tokenizer 若后续引入，只需替换估算函数。
- **4-4 清理默认 dry-run**：`cleanup-agent-data.py` 不默认执行删除；`--execute` 必须配 `--confirm`；
  生产定时排程与备份由运维执行（脚本不内置调度，避免“自动删了没人知道”）。

## 2026-11-04 · 评测护栏与“无 verified 样本”口径（5-1/5-2）

- 评测流水线**只有 `status=verified` 的用例进准确率分母**；`draft`/`example-only` 只做结构校验。
  没有 verified 用例时输出 **BLOCKED（退出码 2）**，报告 accuracy=null；CI 把 2 当 warning 而不是失败。
  理由：把 0%/100% 写进报告会制造“评测已通过/质量很差”的假信号（AGENTS §10）。
- 配置保存护栏默认 **关闭**（`agent.evalGateEnabled=false`）；开启后按“当前库内版本”最新报告判定：
  无报告/非 scored/低于基线 → HTTP200+code409；`force=true` + 原因≥10 字才放行，
  WARN + change_note 追加「[强制跳过评测] 原因」。新增配置不拦（尚无历史版本可评测）。
- 报告只增不改：评测是证据；`report_json` 不写日志（可能含用例原文）。
- 回退率口径：`fallbackRetrievals / retrievals`（fallback_reason 非空计回退；0 次检索 = 0.0）。
  “<15%”是治理目标，不是当前结论；无真实流量时页面显示真实分子分母，不把空数据当达标。
