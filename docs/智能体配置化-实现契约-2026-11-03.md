## 3. 数据模型（已落库的口径）

### 3.1 `agent_config`
字段见 `docs/ddl/agent_config.sql`。要点：
- `code` UK，内置固定 `restock/fault/chat`；自定义 `^[a-z][a-z0-9_]{2,31}$`；
- `version` 每次保存 +1；`builtin=1` 不可删除、不可改 `code/runtime`；
- `model` 空串/NULL = 走 `DKD_AGENT_LLM_MODEL`（**未配置=现状**）；
- `params_json` 结构：restock `{quantile, coverage_days, service_factor, factor_min, factor_max, batch_size}`；
  fault `{window_hours, confidence_order_threshold}`；chat `{}`；
- 区间/默认值以 `agent_defaults.PARAM_SPECS` 为准（Java 侧镜像成常量，见 §4.4）。

### 3.2 `agent_config_history`
`snapshot` = 整行 JSON，**键名与列名一致（snake_case）**，`params_json` 内嵌为对象，`version` 为快照版本。
回滚 = 复制历史快照为**新版本**（current.version + 1），不原地回退。

### 3.3 `agent_log`
本次只建表；写入/清理/页面下批（4-4）。

## 4. Java 契约（java-config）

### 4.1 路径与权限
统一前缀 `/manage/agent/config`。**不经 `/agent` 网关**。
| 方法 | 路径 | 权限点 |
| --- | --- | --- |
| GET | `/manage/agent/config/list` | `manage:agentConfig:list` |
| GET | `/manage/agent/config/{id}` | `manage:agentConfig:query` |
| GET | `/manage/agent/config/{id}/history` | `manage:agentConfig:query` |
| GET | `/manage/agent/config/meta` | `manage:agentConfig:query` |
| POST | `/manage/agent/config` | `manage:agentConfig:add` |
| PUT | `/manage/agent/config/{id}` | `manage:agentConfig:edit` |
| PUT | `/manage/agent/config/{id}/enabled` | `manage:agentConfig:edit` |
| POST | `/manage/agent/config/{id}/rollback` | `manage:agentConfig:rollback` |

写接口必须加 `@Log(title = "智能体配置", businessType = ...)`；Service 写方法 `@Transactional`。
Controller 只做参数校验 + 调 Service + 包 `AjaxResult`；不得直接调 Mapper。

### 4.2 响应规范
- 成功：RuoYi `AjaxResult.success(data)` / 列表 `TableDataInfo`；
- **字段校验失败**：HTTP 200，`{code:400, msg:"<首个错误>", data:{"<field>":"<message>"}}`；
- **业务错误**（不存在/不允许的动作）：HTTP 200，`AjaxResult.error(msg)`（code=500，RuoYi 惯例）；
- **乐观锁冲突**：**HTTP 409**，`{code:409, msg:"配置已被他人更新，请刷新后重试", data:{"version":"当前版本 x，提交版本 y"}}`；
- 不返回任何密钥/连接串（配置里本来也没有）。

### 4.3 请求体
`AgentConfigDto`（编辑时必带 `version`）：
```json
{
  "id": 1, "code": "restock", "name": "智能补货 Agent", "description": "...",
  "runtime": "restock", "scene": 2, "builtin": 1,
  "systemPrompt": "...", "tools": "list_restock_suggestions,...",
  "model": "", "temperature": null, "maxTokens": null,
  "timeoutS": 60, "maxRetries": 2, "paramsJson": {"quantile":0.75},
  "enabled": 1, "disabledReason": null, "version": 3, "changeNote": "..."
}
```
出参 `AgentConfigVo` 字段同构，另加 `createBy/createTime/updateBy/updateTime`。

### 4.4 校验规则（Service 层，字段错误走 §4.2）
| 字段 | 规则 |
| --- | --- |
| name | 必填，2~30 字；`del_flag='0'` 内唯一 |
| code | 新增必填且匹配 `^[a-z][a-z0-9_]{2,31}$`；编辑只读 |
| description | 必填，≤200 字 |
| runtime | 新增只允许 `chat`（Q1）；编辑只读；内置行只读 |
| builtin | 新增强制 0（不允许造内置）；编辑只读 |
| scene | 新增（chat 自定义）= 当前最大 scene+1，且 ≥101（1~4 保留）；编辑只读 |
| system_prompt | runtime=chat/restock 必填 100~8000 字；runtime=fault 忽略（置 NULL）；占位符只允许 §1 白名单，出现 `{未知}` → 字段错误「不支持的占位符 {xxx}」 |
| tools | runtime=chat 必填 ≥1 个且全部在 `TOOL_WHITELIST_BY_RUNTIME[chat]`；restock/fault 必须为空 |
| model | 空/null 或 ∈ `["deepseek-chat","deepseek-reasoner"]`（与 Python `MODEL_WHITELIST` 同步，改一处必须同时改两处 + 通知 Lead） |
| temperature | null 或 0~2（>1.2 前端黄字提示，后端不拒） |
| max_tokens | null 或 256~8192 |
| timeout_s | 5~300 |
| max_retries | 0~5 |
| paramsJson | 按 runtime 逐字段校验区间；restock 要求 `factor_min < factor_max`；chat 必须为 `{}`/null |
| enabled | 0/1；`enabled=0` 时 `disabledReason` 必填 5~100 字 |
| builtin 保护区 | 内置行不可改 code/runtime/builtin；其余字段允许改（停用需原因） |
| 删除 | **本期不提供 delete 接口**（配置停用即可；避免与 `agent_config_history` 引用断裂） |

### 4.5 版本与回滚
- 编辑：`UPDATE ... WHERE id=? AND version=?`，影响行数 0 → 409；
- 同事务内：更新主表 → `version+1` → 插入 `agent_config_history`（snapshot = 更新后的整行）；
- `disabled` 变更同样 +1 并写 history；
- 回滚：读 `(code, version)` 快照 → 以「新版本」写入主表（`version = current.version + 1`，`changeNote` 默认「回滚至 vX」）→ 再写一条 history；
- 回滚同样受乐观锁保护（请求带当前 version）。

### 4.6 元数据接口
`GET /manage/agent/config/meta?runtime=chat` → `AjaxResult.data`：
```json
{
  "runtimes": [{"code":"chat","label":"对话载体","creatable":true},
               {"code":"restock","label":"补货载体","creatable":false},
               {"code":"fault","label":"诊断载体","creatable":false}],
  "models": ["deepseek-chat","deepseek-reasoner"],
  "tools": ["build_device_diagnosis","..."],
  "placeholders": ["focus","tool_list","write_guidance"],
  "defaultPrompt": "你是「帝可得（DKD）...",
  "defaultParams": {"quantile":0.75,"...":0},
  "paramSpecs": [{"key":"quantile","type":"float","min":0.5,"max":0.99,"default":0.75}],
  "sceneBase": 101
}
```
> `defaultPrompt`/`paramSpecs` 用于「恢复默认」与动态表单；**Java 常量必须与
> `agent_defaults.py` 保持一致**（本批以契约表为准，后续可用脚本比对）。

### 4.7 保存后重载通知（异步、失败只 WARN）
- `POST {agent.baseUrl}/agents/config/reload`，头 `X-Agent-Secret: {agent.secret}`，body `{}`；
- 超时 3s（新增 `AgentProperties.configReloadTimeoutMs`，默认 3000；`configReloadEnabled` 默认 true）；
- **异步**执行（`CompletableFuture.runAsync` 或现有线程池），不得让保存失败/变慢；
- 成功 200；任何异常只 `log.warn`（含状态码/异常类型，不记 body）——TTL 30s 是兜底；
- 不因此改动网关白名单。

### 4.8 测试门槛
- Service 单测（Mockito 打桩 Mapper）：正向保存 + 乐观锁冲突 + 各字段拒绝路径（至少：名称重复、未知占位符、tools 越界、factor_min>=factor_max、停用无原因、编辑内置改 code）；
- 回滚用例：快照→新版本、history 再追加；
- 不连真库（AGENTS §8）。

## 5. Python 契约

### 5.1 `app/config_store.py`（python-store）
```python
@dataclass(frozen=True, slots=True)
class AgentConfigSnapshot:
    code: str; name: str; runtime: str; scene: int; builtin: bool
    system_prompt: str | None; tools: tuple[str, ...]
    model: str | None; temperature: float | None; max_tokens: int | None
    timeout_s: int; max_retries: int
    params: dict[str, float | int]
    enabled: bool; version: int

class ConfigStore:
    def __init__(self, *, loader: Loader | None = None, ttl_s: float = 30.0) -> None: ...
    async def get(self, code: str) -> AgentConfigSnapshot | None: ...
    async def get_by_scene(self, scene: int) -> AgentConfigSnapshot | None: ...
    async def list_enabled(self) -> list[AgentConfigSnapshot]: ...
    def invalidate(self, code: str | None = None) -> None: ...

async def get_config_store() -> ConfigStore: ...   # 进程单例
def reset_config_store() -> None: ...              # 仅测试用
async def resolve_chat_scene(scene: int) -> AgentConfigSnapshot | None: ...
```
- **三重回落**（任何一条命中都返回 `None`，调用方回代码默认 + WARN）：
  1. 总开关 `DKD_AGENT_CONFIG_FROM_DB=false`；
  2. 表不存在（MySQL 1146）/DB 不可达/查询异常；
  3. JSON 损坏/runtime 非法。
- 数值不合法**不返回 None**：按 `agent_defaults.normalize_params` 夹取/回落 + WARN；
- TTL 30s（`DKD_AGENT_CONFIG_TTL_S` 可配）+ `get` 命中时比对缓存版本（同一 TTL 内不查库）；
- `invalidate()` 清 code/全量缓存；`/agents/config/reload` 调用它；
- **读取 SQL 必须限定** `del_flag='0' AND enabled=1`；只 SELECT（不写配置表）；
- DB 读取失败日志：表不存在（1146）用 WARN 一次即可（避免刷屏），其他异常 WARN 带异常类型。

**新增设置（`app/config.py`）**：
| 字段 | env | 默认 |
| --- | --- | --- |
| `config_from_db` | `DKD_AGENT_CONFIG_FROM_DB` | `True` |
| `config_ttl_s` | `DKD_AGENT_CONFIG_TTL_S` | `30.0` |

**`app/db.py`**：新增 `AGENT_READ_ONLY_TABLES = {"agent_config", "agent_config_history"}`，
只允许 **读**；`assert_table_allowed(writable=True)` 对它们必须拒绝（配置只能 Java 写）。

**`app/api/ops.py`** 新增（服务间密钥）：
- `POST /agents/config/reload` → `{"code":200,"msg":"ok","data":{"invalidated":true}}`；
- `GET /agents/config/effective?code=restock` → `{"code":200,"data":{"source":"db|default","config":{...}|null}}`
  （只读排障用；不含密钥；`source=default` 表示回落生效）。

**`tests/conftest.py`**：统一设置 `DKD_AGENT_CONFIG_FROM_DB=0`（保持既有 538 用例行为不变），
配置相关测试自行覆盖该旗标或用假 loader 注入。

### 5.2 载体接入（python-carrier）
#### chat
- `ChatRequest.scene`：`int`，`ge=1`（去掉 `le=4`）；端点**建流前**校验：
  - `scene ∈ {1,2,3,4}`：取 chat 行配置；配置不存在 → 现状（代码默认）；`enabled=0` → HTTP 400「该智能体已停用（原因）」；
  - `scene ≥ 101`：按 scene 查已启用 chat 配置；查不到 → HTTP 400「场景不存在或未启用」；
- `system_prompt()` 增加 `base_prompt_override: str | None = None`：
  - 用 override 做模板，仍拼 `focus/tool_list/write_guidance`；
  - override 渲染失败（未知占位符/花括号）→ 回落默认模板 + WARN，**不得抛穿**；
- 工具：`build_chat_graph` 增加 `tools_provider: Callable[[int], list] | None`（每次 respond 节点调用时求值，
  保证配置改后下一次调用生效；ToolNode 注册仍是全量并集）；
  - 内置场景 2/3：沿用 `tools_for_scene(scene)`（行为不变）；
  - 自定义场景（≥101）：按配置 `tools` 从工具注册表过滤；配置写坏 → 空工具 + WARN；
  - 场景 1/4：`[]`（行为不变）；
- LLM 参数：`llm.build_chat_model(..., temperature=None, max_tokens=None, max_retries=None)`；
  `None` = 不传（现状）；有值才注入。chat/restock 都从配置取。
#### restock
- 分析开始时读 `restock` 配置；`params` 覆盖 `Settings.restock_*` 作为本次运行参数；
  配置缺失 → 现状（Settings）；
- 提示词：`restock_calibration.system_prompt(factor_min, factor_max, template_override=None)`；
  seed 模板 = `SYSTEM_PROMPT`，默认参数下渲染结果**逐字相同**；
- LLM 参数（温度/超时/重试/max_tokens）从配置注入；
- `batch_size` 用配置值（缺省 20）。
#### fault
- `DEFAULT_WINDOW_HOURS` 仍是代码默认 24；启动运行参数缺省时取配置 `window_hours`；
- 诊断置信度阈值（`diagnosis.py` 中 “订单异常 ≥2 → high” 的常量）参数化，默认 2；
- 排查清单模板本期不配置化（避免过度设计，清单是代码规则）；
- 行为验收：配置=默认时，同一输入结论与改造前一致。
#### run 埋点（2-8）
- `restock` / `fault` 每次 `start_run(...)` 传 `config_version=<本次实际生效配置版本>`；
- 配置回落/DB 关闭 → `None`（**不编造版本号**）；
- chat 不写 agent_run（现有链路只写 decision_log/message），本期不动。

### 5.3 Python 测试门槛
