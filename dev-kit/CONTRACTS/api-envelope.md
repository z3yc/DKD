# L1 · 统一 API 响应包装契约

> 目标：任何服务的任何接口，外层结构完全一致。调用方写一次解析逻辑，全公司通用。

## 1. 成功响应

```json
{
  "code": "DK0000",
  "message": "ok",
  "data": { },
  "request_id": "01J9Z..."
}
```

## 2. 分页响应（`data` 内的固定形状）

```json
{
  "code": "DK0000",
  "message": "ok",
  "data": {
    "items": [ ],
    "total": 128,
    "page": 1,
    "page_size": 20,
    "has_more": true
  },
  "request_id": "01J9Z..."
}
```

**为什么用 `items` 而不是直接返回数组**：直接返回数组会让"以后想加 total"变成破坏性变更。多包一层，成本为零，收益是永久的扩展性。

## 3. 失败响应

见 `error-codes.md` §3。`data` 在失败时用于携带结构化补充信息（如冲突时的当前状态）。

## 4. 规则

| # | 规则 |
|---|---|
| A1 | **所有接口统一包装**，包括失败；不允许有的接口裸返数组、有的返对象 |
| A2 | `code` 恒为字符串，成功恒为 `<SYS>0000` |
| A3 | `message` 面向终端用户，**生产环境不得含技术细节** |
| A4 | `request_id` **必须存在**，且与日志中的 `request_id` 一致（见 `log-fields.md`） |
| A5 | 分页接口**必须**有 `page_size` 上限（默认 100，最大 500），无上限的分页等于全表扫描 |
| A6 | 时间字段统一 ISO-8601 字符串（`2026-10-27T09:30:00+08:00`），**带时区** |
| A7 | 空值：集合返回 `[]` 不返回 `null`；对象字段缺失时直接省略或给 `null`，**但同一接口必须前后一致** |

## 5. 流式接口（SSE）的例外约定

SSE 不走统一包装（无法包），但要求：
- 每个事件带 `event:` 类型与 `data:` JSON；
- 首个事件必须为 `meta`，携带 `request_id`；
- 错误事件用 `event: error`，`data` 结构与本契约的失败响应一致；
- 结束事件 `event: done`。
