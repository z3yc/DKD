# L1 · 统一错误码契约

> 目标：**同一个错误，在所有子系统里是同一个码、同一套语义**。
> 前端能据此决定"要不要重试、要不要提示登录、要不要报警"，而不是靠解析错误文案。

## 1. 错误码结构

```
<SYS><CC><NN>
 SYS：2 位系统标识（如 DK=帝可得，MY=my-app）
 CC ：2 位类别（见下表）
 NN ：2 位序号
```
示例：`DK0101` = DKD 系统 / 01 参数类 / 01 参数缺失。

## 2. 类别划分（CC）

| CC | 类别 | 客户端行为 | HTTP 建议 |
|---|---|---|---|
| `00` | 成功 | — | 200 |
| `01` | **参数错误**（缺失/格式/越界） | 提示用户修正，**不重试** | 400 |
| `02` | **鉴权失败**（未登录/过期） | 跳转登录/刷新 token | 401 |
| `03` | **权限不足** | 提示无权限，**不重试** | 403 |
| `04` | **资源不存在** | 提示或降级展示 | 404 |
| `05` | **状态冲突**（重复提交/状态不允许/幂等冲突） | 提示当前状态，**不重试** | 409 |
| `06` | **限流** | **可重试**，需退避 | 429 |
| `07` | **依赖不可用**（下游超时/故障） | **可重试** | 503 |
| `50` | **内部错误** | 展示通用文案 + ica 追踪码 | 500 |

**两条铁律**：
1. **`retryable` 由类别决定，不由文案决定**：只有 `06`/`07` 可自动重试。禁止对 `01`/`05` 自动重试 —— 参数错重试一万次还是错。
2. **`05` 状态冲突必须返回当前实际状态**，否则前端无法引导用户。

## 3. 响应体结构（与 `api-envelope.md` 配套）

```json
{
  "code": "DK0501",
  "message": "该设备 24 小时内已存在待执行工单",
  "data": { "existing_task_id": "T20261027001", "status": "PENDING" },
  "request_id": "01J9Z8Y7X6W5V4U3T2S1R0Q9P8"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | ✅ | 错误码，见上 |
| `message` | ✅ | **面向用户**的文案；生产环境**不得包含堆栈、SQL、内部路径** |
| `data` | ⭕ | 结构化补充（冲突时带当前状态） |
| `request_id` | ✅ | 贯穿全链路，用于日志检索 |

## 4. 各语言实现要点

| 语言 | 落地方式 |
|---|---|
| Python | `DomainError(code, message, data, retryable)` + FastAPI `exception_handler` 统一捕获 |
| Java | `BizException extends RuntimeException` + `@RestControllerAdvice` 全局处理 |
| Vue | `api/*.js` 统一拦截：按类别决定提示方式，`06/07` 走退避重试 |

## 5. 禁止事项

- ❌ 直接把下游异常文案透传给客户端（泄漏内部实现）；
- ❌ 用 HTTP 状态码代替业务错误码（`409` 无法区分"重复建单"与"状态不允许"）；
- ❌ 业务分支直接 `return {code: 500}` —— 内部错误码必须只由全局兜底产生，业务异常必须有明确类别；
- ❌ 记录日志后又抛出，导致同一错误被记多次（**记一次，抛一次，二选一**）。

## 6. 错误码登记

新增错误码必须登记进本文件的附录表（写在本节下方），含：码值、类别、触发场景、是否可重试、首版日期。**未登记的错误码不允许上线** —— 否则半年后没人知道 `DK0537` 是什么意思。
