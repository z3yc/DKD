# L0-03 · 编码风格与注释约定

## 1. 总原则

> **风格交给工具，评审只管语义。**
> 任何能被 linter 判定的规则，都不应写进评审清单 —— 配置进工具，让它在提交前自动修掉。本文件只规定工具管不了的部分。

## 2. 工具基线（新建项目第一步就配好）

| 语言 | 格式化 | 静态检查 | 强制时机 |
|---|---|---|---|
| Python | `ruff format` | `ruff check`（建议规则集见下） | pre-commit + CI |
| Java |  IDE 统一模板 + 导入顺序 | 编译器告警 + 项目自定义规则 | CI `mvn compile` |
| Vue/JS | Prettier | ESLint | pre-commit + CI |
| SQL | 关键字大写 | 人工（DDL 变更需评审） | 评审 |

**Python 推荐规则集**（line-length 100）：
```
E, F, W, I, N, UP, B, C4, SIM, ASYNC, T20, ANN, PTH
```
- `T20`：禁 `print`，统一 `logging`（AI 生成的调试 `print` 是高频污染）；
- `ANN`：强制类型注解（公开函数签名必须有）；
- `ASYNC`：捕获 async 函数里的同步阻塞调用；
- `I`：导入排序，避免 merge 冲突。

> `noqa` 必须带原因注释：`# noqa: B008 -- 此处需延迟求值，详见 #123`。无理由的 `noqa` 一律打回。

## 3. 跨语言通用风格规则

| # | 规则 | 理由 |
|---|---|---|
| S1 | **一文件一职责**；文件超过 400 行、函数超过 80 行必须拆 | 可读性 + AI 上下文窗口 |
| S2 | **分层单向调用**：Controller → Service → 数据访问；**禁止反向，禁止跨层直连** | 架构腐化头号原因 |
| S3 | **常量不散落**：集中到 `constant`/`enums`，禁魔法字符串与魔法数字 | 改一处漏一处 |
| S4 | **早返回**（guard clause）优于嵌套 if | 降低认知负荷 |
| S5 | **错误必须显式处理**：禁止空 catch、禁止 `except: pass`、禁止吞异常 | 静默失败最难排查 |
| S6 | 金额用 `BigDecimal` / `Decimal`，**禁 float/double** | 精度 |
| S7 | 对外接口的入参必须校验，校验失败返回明确错误码 | 契约见 L1 |
| S8 | **禁止提交注释掉的死代码** —— 删掉，Git 会记住 | 死代码会误导 Agent 以为它还活着 |
| S9 | 公共函数必须有类型注解 / Javadoc（参数、返回、抛出） | — |
| S10 | 时间统一：存储用 UTC 或统一本地时间并**写进 AGENTS.md**，不得混用 | — |

## 4. 注释约定（本篇重点）

### 4.1 注释写"为什么"，不写"做什么"

```python
# ❌ 反例：复述代码
# 遍历任务列表
for task in tasks:

# ✅ 正例：解释动机与约束
# 只处理 24h 内的工单：更旧的记录已被夜间批处理归档，重复计算会导致重复建单
for task in recent_tasks:
```

判断标准：**把注释删掉后，读者会不会问"为什么这么写"？** 会 → 注释有价值；不会 → 注释是噪音。

### 4.2 必须写注释的四种情况

1. **违反直觉的写法**：绕过第三方 bug、性能权衡、兼容性处理。
2. **业务规则的来源**：为什么是这个阈值 / 这个系数 —— 谁定的，什么时候定的。
3. **不变量的维护责任**：调用方必须保证什么、破坏后会发生什么。
4. **未完成或已知缺陷**：`TODO` / `FIXME`，**必须带负责人与日期**。

```java
// TODO(zyc 2026-10-27): 促销因子尚未接入预测模型，当前基线偏保守约 8%
```

无负责人、无日期的 TODO 视为无效，评审直接打回 —— 它会在半年后变成一个谁也不敢动的谜。

### 4.3 文档注释的分级要求

| 对象 | 要求 |
|---|---|
| 对外 API / 公共库函数 | 必写：参数、返回、抛出、示例 |
| 内部业务函数 | 写"为什么"；签名自解释的可不写 |
| 类 | 头部简述职责 + 关键约束 |
| 模块 | 顶部块注释：用途、数据来源、外部依赖 |
| 配置项（`.env.example`） | **每一项**都要注释：默认值、是否必填、影响范围 |

### 4.4 禁止的注释类型

- 复述代码的注释（`i++ // i 加 1`）；
- 情绪化/主观评论（"这里写得很烂，但先这样"）；
- 被注释掉的代码块（删，见 S8）；
- 变更历史（`// 2026-01-01 by zyc 修改`）—— Git 已经有了；
- 自动生成的大段模板注释（无信息的 Javadoc 骨架）。

### 4.5 AI 生成代码的额外要求

AI 写的代码有个典型问题：**注释完美、逻辑错误**，而且注释会掩盖错误。因此：

- 评审时**先读逻辑，再读注释**；发现注释与实现不符，以"实现为准"并要求修正注释；
- 禁止让 AI 生成"为了看起来完整"的注释；
- 关键业务分支，要求 AI 在注释里写明**它假设的前提**（例："假设传入的 task 已通过区域校验"），便于人快速发现前提不成立的情况。

## 5. 异常处理约定

| 规则 | 说明 |
|---|---|
| 业务异常 vs 系统异常 | 业务异常（参数错、状态冲突、不存在）用**统一业务异常 + 错误码**；系统异常（DB 挂、网络超时）用技术异常并记录堆栈 |
| 不暴露内部细节 | 生产环境**不返回堆栈与 SQL**给客户端；详细堆栈只进日志（见 L1 错误码契约） |
| 异常链保留 | 包装时必须保留 cause，禁止 `throw new RuntimeException("失败")` 丢掉原异常 |
| 重试语义 | 可重试的失败必须显式标注（错误码带 `retryable` 标记），禁止对非幂等操作自动重试 |
| 日志与抛出不重复 | 记录并抛出的，只记一次 —— 不然日志里同一个错出现 5 次 |

## 6. 语言专属补充

**Python**：公开函数签名必须有类型注解；对外契约用 Pydantic 模型；禁 `print`；async 路由内禁同步阻塞（用 `run_in_executor`）；导入按标准库/第三方/本地三段。

**Java**：接口 `IXxxService` + 实现 `XxxServiceImpl`；Controller 不写业务逻辑、不直连 Mapper；常量 `static final`；金额 `BigDecimal`；时间 `Date`/`LocalDateTime` 统一。

**Vue/JS**：组件多词 PascalCase；API 调用统一走 `src/api/<域>.js`，禁组件内裸 axios；异步 loading 必须在 `finally` 复位；长请求必须可取消（AbortController）；`v-html` 内容必须过 sanitize。
