## 1. 这里什么最重要（按重要性排序）

1. **数据一致性**：任何写入必须经 Service 层的事务与校验链；绕过会产生重复或脏数据。
2. **幂等**：同一请求重复提交不得产生重复记录（外部重试与用户双击都是常态）。
3. **可观测**：每个关键决策必须留痕，否则线上问题无法归因。
4. 接口契约稳定：外层统一包装，不得出现裸数组/裸对象混用。

## 2. 失败长什么样

- 文档失败 = **它在撒谎**：接口文档写了实际不存在的字段，比没写更糟（调用方按文档写死）。
- 配置失败 = **它转错路由**：错配比漏配危险 —— 漏配会启动报错，错配会静默跑错库。
- 数据失败 = **它静默产生错误结果**：最危险，必须有对账或断言兜底。
- 依赖失败 = **超时后被重试放大**：非幂等接口被重试 = 重复写入。

## 3. nit 上限

- 一次评审最多提 **3 条** nit；超过说明该改的是 lint 规则，不是这次的 PR。
- 不提：纯格式化、lint 已覆盖的、与本次改动无关的历史问题。

## 4. 跳过这些路径

- 自动生成产物（如 `*_pb2.py`）

## 5. 证据要求

- 每个发现必须给出 **文件:行**；凭名字猜测的一律无效。
- 摘要以计数开头：`"3 个问题：1 个重要，2 个 nit"`。
- 没问题就明确说 **nothing to fix**，不要硬凑。
- 区分 `Important` / `Nit` / `Pre-existing`（后者不是本次改动引入的，不算作者过错）。
