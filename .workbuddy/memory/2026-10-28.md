### 复核确认的高影响结论（后续勿忘）
1. **交易链路断链（P0）**：`InventoryServiceImpl.updateInventoryQuantity`（dkd-manage）全仓**零调用方**；
   `OrderController.add()`→`insertOrder()` 无库存扣减/无金额校验/无幂等。
   → 目前唯一库存增量来源是**补货工单完成**（dkd-app `TaskServiceImpl.complete`，单事务串写 4 张表）与后台 CRUD。
   → 影响：压测前必须先定性，「下单链路性能」当下无意义。
2. **全仓无 CI**（.github/.gitlab-ci/Jenkinsfile/drone/azure 等穷举均未找到），而 `dkd-parent/Dockerfile:25`
   注释称「测试由 CI 负责」——属于文档与实际的落差。README §七 的 203/42/16 基线无自动门禁固化。
3. 根 `.env.example` **确实存在且已入仓**（一处探索结论报错，已纠正）。
4. 前端三份锁共存（`package-lock.json` 2025-10 早于 `package.json` 2026-04），Dockerfile 用 `npm ci` → 构建可复现性风险。
5. 日志卷挂载（`admin_logs:/app/logs`）与 `logback.xml` 的 `/home/ruoyi/logs` 不一致 → 容器重建丢日志。

### 架构要点（跨会话复用）
- 工单主链路：创建在 **dkd-parent** `TaskServiceImpl.insertTaskDtoInternal`（9 步校验链）；**接单/完成在 dkd-app**，
  两套工程、两套身份体系（SysUser vs tb_emp+自签 JWT），JWT 互不相认，仅共享 MySQL 库 `dkd` 与 Redis db0。
- `TaskDetailsDto.expectCapacity` 语义坑：注释写「容量」，dkd-app 侧当作**补货数量累加进库存**。
- 状态常量跨模块重复且类型不一致：`DkdContants`(Long) vs `VmSystemConstant`(Integer)。
- 容器编排：Dockerfile 在**各子系统根目录**，`deploy/docker/` 下没有 Dockerfile；部署硬依赖「导入业务库 dump」
  （tb_* DDL 不在仓库）。
- dkd-agent Windows 启动必须 `uv run python -m app` 或 `--loop none`（uvicorn 0.36+ 强制 Proactor，psycopg 异步不支持）。
